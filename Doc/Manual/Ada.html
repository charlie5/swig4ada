This chapter describes the Ada module of swig4ada, a fork of SWIG which generates Ada bindings to C and C++ libraries. The module is not part of the SWIG distribution.

41.1 Overview

The Ada module makes a thin binding: each declaration of the library has a counterpart in Ada of the same name, and a record has the layout of the structure or class which it stands for. An Ada program can therefore declare an object of a C++ class as a variable of its own, pass it to the library, and read its public members directly. A binding which is more comfortable to use from Ada (a thick binding) is something which is written by hand, on top of the thin one.

Two files of each kind are generated:

  • A set of Ada package specifications (.ads files). There are no package bodies.
  • A wrapper file in C or C++ (example_wrap.c or example_wrap.cxx), which holds a small function for each function of the library, and is compiled and linked with the Ada program.

The module needs the GNAT compiler. C is bound with the facilities of the Ada standard alone (Interfaces.C and convention C), but C++ classes are bound with GNAT's convention CPP, which no other Ada compiler provides. The layout of records and the mangled names which are imported are those of GCC on the machine which generates the binding (the Itanium C++ ABI and, for the classes of the C++ standard library, GNU libstdc++).

41.1.1 Known shortcomings

  • A class with virtual functions which inherits a base class virtually, and also has a base with virtual functions which it does not inherit virtually, is bound with a warning: its record is a type extension, which GNAT lays out, with storage for its virtual base which is no smaller than C++ takes, and the base is reached by as_<base> alone. Any other class with a virtual base has the layout of its class (see Layout), but no type may be derived in Ada from one with virtual functions.
  • Of several base classes which have virtual functions, the first is the parent of the Ada type. The others are reached through a function (see Inheritance), and a function which overrides one of theirs cannot be overridden again in Ada.
  • Directors are not needed for most virtual functions: a C++ class with virtual functions is derived from directly in Ada. A director is made only for a function which Ada cannot override so (see Directors).
  • A declaration which uses a type that SWIG has not been shown is left out of the binding, with a warning.
  • A pointer to a class member is laid out as the Itanium C++ ABI has it (GCC and Clang, on each machine but Windows). It can be given back to C++, not called through in Ada.
  • An object which C++ has made cannot be converted to a derived type in Ada, nor tested for membership of one (see Inheritance).
  • std::auto_ptr is not bound, and std::unique_ptr only where an instance of it is named with %template.
  • A binding is generated for one machine. The wrapper file checks the layout of every record when it is compiled (see Layout), so a binding which is taken to a machine where a structure differs fails to build there, and must be generated again.

41.2 Preliminaries

41.2.1 Running SWIG

Suppose that a library is described by this interface file: 

/* File: shapes.i */
%module shapes

%include <std_string.i>

%{
#include "shapes.h"
%}

%include "shapes.h"

The binding is generated with the -ada option, and -c++ where the library is in C++: 

$ swig4ada -ada -c++ shapes.i

This writes the wrapper file shapes_wrap.cxx and the specifications shapes.ads, shapes-binding.ads and one for each class, into the current directory (or the one named by -outdir). The specifications are written with little regard for their appearance, and are usually tidied with a pretty printer: 

$ gnatpp -rnb *.ads

41.2.2 Command line options

The options which are particular to Ada are:

Ada specific options
-debug-log Write a record of what the module does to swig4ada-debug.log, in the current directory. Setting the environment variable SWIG4ADA_DEBUG does the same.
-namespace <package> Generate the packages of the module as children of the package which is named (outer.shapes, in outer-shapes.ads). That package is not generated: it must exist, and may be one of the program's own.
-no-check-layout Check the layout of a class, when the wrapper file is compiled, only where its record has a representation clause. By default every class whose layout can be worked out is checked.

The general options of SWIG apply as usual, among them -I, -D, -outdir, -o and -w. The symbols SWIGADA and SWIGAda are defined when an interface file is read, for conditional compilation. SWIG's parser does not read GCC's attributes, which a library's headers may put in a macro of their own (__attribute__((visibility("default")))); an interface file makes them nothing for SWIG's reading with #define __attribute__(x), which changes nothing of what the wrapper includes.

41.2.3 Compiling and linking

The specifications need four support packages, which come with swig4ada and must be on the source path of the program:

  • swig and swig.Pointers, which declare the types that the bindings share (swig.void_ptr, swig.bool, pointer and array types of the standard C types).
  • swig.Guards, a generic which destructs an object of a C++ class when it leaves its scope.
  • swig.std_Strings, the binding of std::string, needed where the interface file includes std_string.i.

A program may also use swig.Exceptions (see Exceptions). The wrapper file is compiled as C or C++ and linked with the program, most simply by a GNAT project which names both languages: 

project Shapes is
   for Languages   use ("Ada", "C++");
   for Source_Dirs use (".", "path/to/the/support/packages");
   for Main        use ("demo.adb");

   package Linker is
      for Default_Switches ("Ada") use ("-lshapes", "-lstdc++");
   end Linker;
end Shapes;

41.3 The shape of a binding

For a module shapes, these packages are generated:

Package Holds
shapes The simple types (enumerations, typedefs of numbers), the constants and the variables.
shapes.Binding The functions which are not members of a class. A variable or constant whose type is declared in a child package is here too, as the top package cannot see its children.
shapes.Pointers, shapes.pointer_Pointers Pointer types, and pointers to pointers, of the simple types.
shapes.<class> One package for each structure, union and class, and for each type of pointer to a function. The type itself is Item, with Item_Array, Pointer, Pointer_Array and Pointer_Pointer, and the member functions follow. A pointer of three levels or more (T***) is a swig.void_ptr, an address.
shapes.<class>.Guards For a class with a virtual destructor: an instance of swig.Guards.

C and C++ tell names apart by their case, and Ada does not. Where two names of a package would be the same in Ada, the later of two types or packages is given a numeric suffix (Hi0_2), and a variable, constant or function is prefixed with the_. A name which is a reserved word of Ada is prefixed in the same way.

41.4 Basic C wrapping

41.4.1 Functions

A function is imported in shapes.Binding, by way of its function in the wrapper file: 

double distance (Point a, Point b);

function distance (a : in shapes.Point.Item;
                   b : in shapes.Point.Item) return Interfaces.C.double;

A structure which is passed by value is passed as C passes it; nothing is copied to the heap. A parameter which has no name in the header is called arg_1, or arg_<n> by its place where there are several.

A function of a variable number of arguments (int log (const char* fmt, ...);) is bound with the arguments which are named, and with those which %varargs names.

With %include <typemaps.i>, a pointer or reference which is marked as an input is passed by value, and one which is an output or both stays a pointer: 

%apply double *INPUT  { double *a, double *b };
%apply int    *OUTPUT { int *whole };

double add   (double *a, double *b);
void   split (double x, int *whole);

function  add   (a : in Interfaces.C.double;
                 b : in Interfaces.C.double) return Interfaces.C.double;

procedure split (x     : in Interfaces.C.double;
                 whole : in swig.Pointers.int_Pointer);

41.4.2 Variables and constants

A global variable is an Ada variable which is imported, so it is read and assigned to directly. A constant made by #define, %constant or const with a value is an Ada constant with that value, which SWIG works out from the C expression: 

#define MAX_SIDES 12
#define MASK      (0xF0 | (1 << 2))
#define NAME      "shapes"
#define SCALE     2.5
#define ALL_ONES  ((unsigned) -1)
#define SEVENTH   ((float) 1.0 / 7)
extern int shape_count;

MAX_SIDES   : constant := 12;
MASK        : constant := 244;
NAME        : aliased constant Interfaces.C.Strings.chars_ptr
            := Interfaces.C.Strings.New_String ("shapes");
SCALE       : aliased constant Interfaces.C.double   := 2.5;
ALL_ONES    : aliased constant Interfaces.C.unsigned := 4294967295;
SEVENTH     : aliased constant Interfaces.C.C_float  := 1.428571492433548E-01;
shape_count : aliased Interfaces.C.int;

A constant of type int is a named number, which may be used as any integer. A constant of any other type is a constant of the Ada type of its C type: of the type which is declared, for a const or a %constant, and for a #define of the type of its value, as C would give it (a cast gives its own type, so ALL_ONES is an unsigned, and a literal with the suffix f is a float).

The value is worked out as C works it out, from numbers (decimal, octal, hexadecimal or binary), characters, sizeof a standard type, the constants which are known (those of the module, of the enumerations and of earlier #defines), and the operators of C, applied with C's precedence. A cast is applied as C applies it, in each of its forms: (unsigned) -1, static_cast<unsigned> (-1) and unsigned (-1) are each 4294967295, as a cast to an integer type is modulo the size of the type and within its range ((signed char) 200 is -56), a cast to bool gives 0 or 1, and a cast of a real number to an integer type truncates it ((int) 2.5 * 2 is 4). A typedef of the module is applied as the type which it names (with typedef unsigned char byte_t;, byte_t (300) is 44), and a cast to a type which is not known, such as an enumeration, leaves the value as it is.

A real number is worked out likewise, with +, -, *, / and brackets, each operation in the type in which C works it out: of two integers in an integer, which truncates a division (7 / 2 + 0.25 is 3.25), of a double in double, and otherwise, where it has a float, in float (1.0f / 7 * 3.0f is not the double 1.0 / 7 * 3.0 rounded to float, and SWIG gives the value which C gives). This is as C works it out on a machine whose FLT_EVAL_METHOD is 0, as x86-64 and AArch64 are. So const real later = eps * 2; is a constant of twice the value of eps. The value is written with the fewest digits, of 15, 16 or 17, which give back the double exactly, so a constant is the same number in Ada as in C. SWIG works the value out, and does not leave it to Ada as an expression, because Ada works out a static expression exactly and rounds it once, which need not give C's value.

A constant whose value cannot be worked out is given as it is written, where that is made of numbers and of constants of the module; otherwise (an expression which uses ?: or calls a function, say) it is left out with a warning. A real constant whose value is beyond the range of its type (#define HUGE_VAL 1.0e10000, which C takes for infinity) is left out with a warning too. A #define which names something other than a value, such as a type (#define INT unsigned int) or a pointer ((char *) 0), is no constant.

A variable is imported by the name which the library knows it by, whatever %rename calls it in Ada. A variable which has no symbol outside its own file cannot be imported: one which is static and, in C++, one which is constant and not extern. Where its value is worked out it is a constant of that value (a number, a bool, a char, a value of an enumeration, or the text of a constant pointer to a string literal, const char* const NAME = "shapes";, as for a #define), and otherwise it is left out with a warning. A type of the C library which a header names in the namespace std (std::size_t, std::int32_t) is the type itself (interfaces.C.size_t).

41.4.3 Enumerations

An enumeration is an Ada enumeration type with a representation clause, so its literals have the values which C gives them. Ada requires those values to rise, so the literals are declared in the order of their values, and a literal which repeats the value of another is a constant of the type. 

enum Colour { Red, Green = 5, Blue };

type Colour is (Red, Green, Blue);
for  Colour use (Red => 0, Green => 5, Blue => 6);
pragma Convention (C, Colour);

An enumeration with no name gives constants. An enumeration which names its underlying type (enum Small : unsigned char) is given the size of that type.

41.4.4 Structures and unions

A structure is a record of convention C in a package of its own, whose components are those of the structure, in their order and with their names: 

struct Point { double x; double y; };

package shapes.Point is

   type Item is record
      x : aliased Interfaces.C.double;
      y : aliased Interfaces.C.double;
   end record;

   type Item_Array is array (Interfaces.C.size_t range <>) of aliased Item;
   ...
   subtype Pointer is C_Pointers.Pointer;

A union is an unchecked union. A structure with bit-fields is given a full record representation clause, as GNAT does not place bit-fields as C does. A structure or union with no name which is declared within another is given a type of its own, named <outer>_<member>. A structure which is declared and never defined is an opaque type, used through its pointer. A class of C++ with no members is a null record of one byte, as C++ gives it, so that a member of its type takes the place which it takes in C++.

41.4.5 Pointers, arrays and strings

A pointer to a structure is Pointer of its package, an instance of Interfaces.C.Pointers, so pointer arithmetic is available. A pointer to a standard C type is in swig.Pointers (swig.Pointers.int_Pointer), and void* is swig.void_ptr. An array member or variable is an Ada array with the bounds of the C array, indexed from 0.

A char* is Interfaces.C.Strings.chars_ptr, and so is a pointer to a typedef of char (const char_t*, where typedef char char_t;, or the LPSTR of Windows). A pointer to a typedef of signed char or unsigned char is taken for a pointer to bytes, and has a pointer type of its own. The binding does not convert strings: the caller makes one with New_String and frees it, and reads one with Value.

41.4.6 Pointers to functions

A pointer to a function is an access to subprogram type of convention C, in a package named after its typedef. An Ada function which is to be called by the library must be declared at library level, with pragma Convention (C, ...). 

typedef int (*Visitor) (Shape* s);
int visit_all (Visitor v);

package shapes.Visitor is
   type Item is access function (arg_1 : in shapes.Shape.Pointer)
                                 return Interfaces.C.int;
   pragma Convention (C, Item);

A pointer to a class member is a record of the package swig: a pointer to a member function is swig.member_function_Pointer (two words: the address of the function, or its place in the table of virtual functions, and the adjustment of this), and a pointer to a member variable is swig.member_data_Pointer (its offset). A typedef of one is a subtype of it. Ada takes such a pointer from C++, as the result of a function, a variable or a constant, and gives it back, as C++ alone can call through it. A constant (%constant double (Shape::*AREAPT) (void) = &Shape::area;) is a constant object which the wrapper defines, and is bound as a constant which imports it. 

typedef double (Shape::*Measure) (void);
Measure area_of ();
double  measure (Shape* s, Measure m);

the_Area : constant shapes.Measure := shapes.Binding.area_of;
...
X := shapes.Binding.measure (the_Square'Unchecked_Access, the_Area);

41.5 Basic C++ wrapping

41.5.1 Classes

A class has a package of its own, and is bound in one of three ways, according to how C++ treats its objects:

  • A class with no virtual function, which declares neither a destructor nor a copy constructor (and has no base class or member which does), is a plain record, as a structure is. Ada may copy and assign it.
  • A class which declares a destructor, or a copy or move constructor (one which is not defaulted), which can be neither copied nor moved, or which has a virtual base class, is passed and returned by C++ through a hidden pointer. It is a limited record of convention CPP: Ada can neither copy nor assign it.
  • A class with a virtual function is a tagged limited record of convention CPP, whose tag is the pointer to the table of virtual functions of C++. Its Pointer is class-wide, and a call through it dispatches.

The kind is told from what SWIG is shown of the class. Where a base class or a member is of a type which SWIG has not been shown, a class which nothing else marks as one which C++ constructs is taken for a plain record, and the warning (862) of that base or member says so: should what is not known have a destructor or a copy constructor of its own, C++ constructs the class, and the functions which pass or return it by value are bound wrongly. Showing SWIG the type, or a library file for it, settles it. 

class Shape {
public:
  Shape ();
  virtual ~Shape ();
  virtual double area () const = 0;
  void   move (double dx, double dy);
  Point  centre;
  static int total ();
};

package shapes.Shape is

   type Item is abstract tagged limited record
      centre : aliased shapes.Point.Item;
   end record;
   pragma Import (CPP, Entity => Item);

   type Pointer is access all shapes.Shape.Item'Class;

   function  construct return shapes.Shape.Item'Class;

   procedure destruct_0 (Self : in out shapes.Shape.Item);
   procedure destruct   (Self : in out shapes.Shape.Item);

   function  area  (Self : access shapes.Shape.Item)
                    return Interfaces.C.double is abstract;
   procedure move  (Self : in out shapes.Shape.Item'Class;
                    dx   : in     Interfaces.C.double;
                    dy   : in     Interfaces.C.double);
   function  total return Interfaces.C.int;

Public data members are components of the record. Protected members are bound too, and private data members are present as components so that the record has its right size. A private member function is not bound: where it is virtual its place among the virtual functions is kept, and a call of the function which it overrides dispatches to it. A static member function is a function of the package with no Self, and a static member variable is a variable of the package. A static member which is constant and has its value in the class (static const int limit = 16;, and likewise one of a bool, a char or an enumeration, or one which is constexpr) is a constant with that value, as C++ need give it no symbol.

A class which is nested in another is a class of the module, with a package of its own beside that of the class which holds it: Engine::Gauge is shapes.Gauge. Where two classes each have a nested class of one name, the later one is named after its class as well (shapes.Pump_Gauge). A nested class which is private or protected is bound for its shape alone: its package has its record, whose members are storage, and nothing else, so that a member of the outer class of its type takes its place, and the outer class has its whole layout. A nested enumeration which is private or protected is declared in the package of its class, for the same reason.

A friend function which is defined in a class is a function of shapes.Binding, like any function which is no member. A typedef which a class declares, of a number or an enumeration, is a subtype in the package of the class.

41.5.2 Constructors and destructors

Each constructor is a function construct of the package, which is used to give an object its initial value: 

declare
   the_Circle : aliased Circle.Item := Circle.construct (radius => 2.0);
begin
   put_Line (the_Circle.area'Image);
   Circle.destruct_0 (the_Circle);
end;

GNAT does not call a C++ destructor by itself. An object which is declared in Ada must be destructed by a call of destruct_0 before it goes out of scope, or it leaks whatever it owns. For a class with a virtual destructor there is a guard which does so: 

declare
   the_Circle : aliased Circle.Item := Circle.construct (2.0);
   the_Guard  : Circle.Guards.Guard (the_Circle'Access);
begin
   ...
end;     -- The guard destructs the circle here.

There are two destructors:

  • destruct_0 destructs the object and leaves its storage. It is the one for an object which Ada declared or allocated.
  • destruct destructs the object and then frees it with operator delete. It is only for an object which C++ allocated with new. For a class whose destructor is not virtual the two are the same.

An object of a class which C++ constructs, and which is declared with no initial value, is given its default constructor by GNAT.

41.5.3 Functions which return a class

A function which returns, by value, a class which C++ constructs cannot be an Ada function. It is bound as a procedure with a last parameter Result, which points to an object of the caller; the result replaces that object. 

Label       make_label (const char* text);
std::string describe   (const Shape& s);

procedure make_label (text   : in Interfaces.C.Strings.chars_ptr;
                      Result : in shapes.Label.Pointer);

procedure describe   (s      : in shapes.Shape.Pointer;
                      Result : in swig.std_Strings.std_string_Pointer);

declare
   the_Label : aliased Label.Item := Label.construct (New_String (""));
begin
   make_label (New_String ("north"), the_Label'unchecked_Access);
   ...
   Label.destruct_0 (the_Label);
end;

This is so whether or not the result is declared constant (const Label make_label ();). A class which is a plain record is returned as an ordinary function result.

41.5.4 Inheritance

A class which is derived from a class with virtual functions is a type extension of it, and its functions which override are marked overriding: 

class Circle : public Shape {
public:
  Circle (double radius);
  virtual double area () const;
  double radius;
};

package shapes.Circle is

   type Item is new shapes.Shape.Item with record
      radius_storage : aliased Interfaces.C.double;
   end record;
   pragma Import (CPP, Entity => Item);

   function  construct (radius : in Interfaces.C.double)
                        return shapes.Circle.Item'Class;

   overriding
   function  area       (Self : access shapes.Circle.Item)
                         return Interfaces.C.double;

   function  radius     (Self : access shapes.Circle.Item'Class)
                         return Interfaces.C.double;
   procedure set_radius (Self   : in out shapes.Circle.Item'Class;
                         radius : in     Interfaces.C.double);

C++ may place the members which a derived class adds within the unused end of its base class, where GNAT cannot place the components of a type extension. So a member which such a class adds is read and written through a pair of functions (radius and set_radius), and its component, renamed radius_storage, only reserves the storage: it must not be used.

A base class which is not the parent of the Ada type (a base with no virtual function, or a second base with them) is reached through a function as_<base>, which returns a pointer to that part of the object. A class with no virtual function has each base class as a component, named after it. The functions of such a base are therefore called on the base: Base.width (Derived.as_Base (the_Object).all). One which the derived class names with a using declaration (using Base::width;) is a function of the derived class as well, as it is in C++: Derived.width (the_Object).

A base class which the interface file ignores (%ignore Base;) is still part of each class which is derived from it, so it is bound for its shape alone: its data members are storage (<member>_storage), its virtual functions are bound, as they may be overridden, and nothing else of it is.

A member whose type is not known is left out, and its record no longer matches its class (warning 862), unless it is a smart pointer of the standard library (std::unique_ptr, std::shared_ptr or std::weak_ptr), as the pointer to the implementation of a class most often is (std::unique_ptr<FilePrivate> d;). Such a member is storage of its size (d_storage, and d_storage_2 for a std::shared_ptr), which must not be used, and its class is one which C++ constructs. Where a class of that kind has no constructor in the binding, as each of its constructors takes a type which is not known, a base class or member of its type is storage too (Base_storage), and a base is reached through as_<base>. A component which has the name of one of a parent of the Ada type is given a number (d_storage_3).

A base class may have a function which takes or returns a pointer to a class that is derived from it. The package of the base then has only a limited view of that of the derived class, and names the pointer as access shapes.Circle.Item'Class. A virtual function which overrides another writes each such pointer as the function which it overrides does, as Ada requires the two profiles to conform. The pointer type of a class which C++ constructs, or which is virtual, is declared in a package beside that of the class (shapes.Circle_Pointer, of which shapes.Circle.Pointer is a subtype), so that a function of a package with only a limited view of the class returns a pointer of that type, which is converted to the pointer type of a base class as any pointer is (XMLNode.Pointer (XMLDocument.NewElement (...))). A pointer which is itself constant (const Node* const) is passed as any pointer is.

An object which C++ has made (one which a function of the library returns by pointer) is used through the class-wide type, or through a pointer of its own class which the library gives. It cannot be converted to a derived type in Ada (Circle.Item (the_Shape.all)), nor tested for membership of one: GNAT checks a tag which such an object has not, and raises Constraint_Error. Where the library has a function which narrows a pointer (a dynamic_cast), that is the way to reach the derived class.

41.5.5 Deriving from a C++ class in Ada

An Ada type may extend the record of a C++ class with virtual functions, and override them. C++ then calls the Ada functions, as the object has a table of virtual functions which GNAT has made. No director class is involved, but for the few functions of Directors. 

with shapes.Shape, Interfaces.C;

package Squares is

   type Item is new shapes.Shape.Item with record
      Side : aliased Interfaces.C.double := 1.0;
   end record;

   overriding
   function area (Self : access Item) return Interfaces.C.double;
   pragma Convention (CPP, area);

end Squares;

declare
   the_Square : aliased Squares.Item;     -- The part which is a 'Shape' is made by C++.
begin
   the_Square.Side := 3.0;
   ...                                    -- Given to the library, C++ calls 'Squares.area'.
   shapes.Shape.destruct_0 (shapes.Shape.Item (the_Square));
end;

Each function which overrides is given convention CPP, and the package must be at library level, as C++ calls its functions. The part of the object which is the C++ class is made by a constructor of that class: its default constructor, as above, or another, by an extension aggregate ((Circle.construct (1.0) with Side => 3.0)). An abstract C++ class cannot be constructed by itself, so for one the wrapper file holds a concrete class which is derived from it, and it is that which construct makes; the Ada type then puts its own table of virtual functions in its place.

41.5.6 Directors

A virtual function which returns, by value, a class that C++ constructs, or which takes a plain structure by value, cannot be overridden by an Ada type which is derived from the class: C++ would call the Ada function with its arguments where its own ABI puts them, and the result through a hidden pointer which Ada does not expect. For a class which the interface file marks %feature("director"), as the other languages of SWIG require for any function to be overridden, the binding has a child package Director of the package of the class. Its Item is derived from that of the class, and has a primitive for each such function, which takes what the function of the class-wide type does (the result as a last parameter Result, a structure by reference). An Ada type which is derived from it may override each, and C++ then calls the Ada function: the wrapper file holds a class which is derived from the C++ class, and whose override of the function calls the primitive. A primitive which is not overridden does what the function of the class does, and an Ada function which overrides one may call it so (Speaker.Director.label (Speaker.Director.Item (Self), Result)). Where the function of the class is pure, the primitive is abstract. 

%feature("director") Speaker;

class Speaker {
public:
  virtual ~Speaker ();
  virtual std::string speak (const std::string& word);
};

with voices.Speaker.Director, swig.std_Strings;

package Parrots is

   type Item is new voices.Speaker.Director.Item with null record;

   overriding
   procedure speak (Self   : in out Item;
                    word   : in     swig.std_Strings.std_string_Pointer;
                    Result : in     swig.std_Strings.std_string_Pointer);
   pragma Convention (CPP, speak);

end Parrots;

The Ada function gives its result by replacing the object which Result points to, as the procedures of a binding do (assign, of a string). That object is made by the default constructor of the class of the result, so a function whose result has no constructor which takes nothing cannot be overridden, and is warned of. The director has the constructors of the class, and a type derived from it is constructed by them, as from any class. A function which the class inherits from a base is in its director too, so that a class derived from one with a director may have one of its own. A class which is not so marked, and the other virtual functions of one which is, are overridden in Ada as before; so are a class whose base SWIG has never been shown, and one with a virtual base, which have no director.

41.5.7 Overloaded functions, templates and namespaces

Overloaded functions keep their one name in Ada, which overloads too. Of two functions which Ada cannot tell apart (which differ only in a const, say), SWIG warns as it does for other languages, and the later one is left out. Default arguments give one function for each number of arguments. Of a virtual function with a default argument, the function of all its arguments is the one which dispatches and may be overridden; the others call it. A virtual function which is not bound (one which the interface file ignores, say, or whose types are not known) still has its place among the others, as a procedure unbound_virtual_<n> which must not be called; so has a virtual destructor which is not public, as destruct_0 and destruct. A virtual function which returns, by value, a class that C++ constructs (virtual Status Put (...)), or which takes a plain structure by value, cannot be called through the table of virtual functions from Ada, as C++ takes its arguments otherwise than Ada gives them. It is a function of the class-wide type, which makes the virtual call, and unbound_virtual_<n> has its place; it is overridden in Ada through a director of the class (see Directors). A member whose type SWIG is never shown is left out, with a warning, and the class is still bound: it is then used through a pointer to an object which C++ makes. Likewise the virtual functions of a class with a base class which SWIG is never shown (class E : public Base, where Base is in a header which is not included) are each called through the wrapper, as their places among those of the base are not known. For the standard exceptions, include std_except.i, which declares them with the shape of GNU libstdc++, so that a class derived from one is laid out and dispatches as any other. An operator is a function with a name: operator-> is dereference, and another has the name which the interface file gives it, as upstream's examples give operator+ the name Plus and operator() the name Functor (%rename(Functor) operator ();); one which is given no name is left out, with warning 503 (std_function.i names the operator() of std::function call). A class with an operator-> is a smart pointer, and is given the member functions and the member variables of the class which it points to, called and reached through it: a member variable x is read by x (Self) and set by set_x (Self, ...), the second where the smart pointer gives a pointer which is not constant. One which is a friend of its class is a function of shapes.Binding with both operands as parameters, and one which returns an object gives it through Result.

A template is bound once an instance of it is named with %template; the instance is then a class like any other, with the name which %template gives it. The %template line may follow the functions which use the instance, as it does where a header is included first. A member template of a class (a function, an operator or a constructor) is bound in the same way, by naming its instances within an %extend of the class: 

%extend YAML::Node {
  %template (Node)    Node<int>;                 // A constructor.
  %template (as_int)  as<int>;
  %template (child)   operator[]<std::string>;
}

Where a function has a const overload and one which is not, the two have one profile in Ada, and SWIG keeps the const one (warning 516). The other is bound by a name of its own, given before the class by its parameters (%rename (element) YAML::Node::operator[] (std::string const &);).

Namespaces are not reflected in the package names: a class geometry::Box is the package shapes.Box. The names which are imported from C++ take account of them. A typedef which a using declaration brings into another namespace, or which a class template declares, is followed to the type which it stands for.

41.5.8 References

A reference, constant or not, and an rvalue reference (T&&) are bound as a pointer. Where a function moves from an rvalue reference, the object of the caller is left as its class leaves an object which has been moved from, and must still be destructed.

41.6 The C++ standard library

std::string is the type swig.std_Strings.std_String, a limited record with the layout of the GNU libstdc++ string, with functions to make one from a char_array and to read it (to_std_String, to_Ada, c_str, Length, assign, destruct). The functions which that package needs are added to the wrapper wherever a binding uses a string, whether or not the interface file includes std_string.i. A header which names a string as an instance of its template (std::basic_string<char>, or std::basic_string<wchar_t> for the wstring of std_wstring.i) names the same type.

The containers (std_vector.i, std_list.i, std_deque.i, std_set.i, std_map.i, std_pair.i, std_stack.i, of its default container, and others) are bound like any other class template, so an instance must be named (stl.i includes those of the string, the vector, the map and the pair): 

%include <std_vector.i>
%template (int_Vector) std::vector<int>;

A container is a class which C++ constructs, so it is a limited record. std::pair and std::complex are plain records, which may be assigned and are returned as function results. The streams (std_iostream.i, std_sstream.i) are used by pointer only, whether a header names one by its typedef (std::ostream) or as the instance of its template (std::basic_ostream<char, std::char_traits<char> >). The iterator of a map (std::map<K, T>::iterator) is a class of the layout which GNU libstdc++ gives it, which must be named with %template where a header uses it (%template (Iterator) std::_Rb_tree_iterator<std::pair<const K, T> >;), and so is that of a vector (__gnu_cxx::__normal_iterator<T*, std::vector<T> >). A library's own iterator is used through its operators, which the interface names (%rename (next) Iterator::operator++ ();, and the instances of operator== and operator!= in an %extend). Each container (a vector, a list, a deque, a map, a set and their like) has its allocator as a parameter of the template, with its default, so that a partial specialisation of a library which names it (template <typename T, typename A> struct convert<std::vector<T, A>>) is instantiated for a vector which is named without it (%template (ints_conversion) YAML::convert<std::vector<int> >;).

swigmove.i and std_unique_ptr.i are provided for objects which can be moved and not copied.

41.7 Exceptions

A C++ exception must not pass through Ada code. Where the interface file catches one (a throws typemap, %exception, %catches, or the SWIG_exception macro of exception.i), or a %contract fails, the wrapper function does not raise an Ada exception. It records a pending exception and returns, and the caller asks for it: 

with swig.Exceptions;
...
   the_Result := risky_function (the_Argument);
   swig.Exceptions.check;     -- Raises 'swig.Exceptions.Error' if one is pending.

swig.Exceptions also has is_Pending, pending_Kind, pending_Message and clear. Generated code never calls check itself.

With %include <std_except.i> a function which is declared to throw a standard exception records it by its kind, with its own what (), and the standard exceptions (std::exception, which is the_exception in Ada, as exception is a reserved word, std::logic_error, std::runtime_error and those derived from them) are classes of the module, with their virtual functions in their places, so that an exception class of a library which is derived from one of them is bound whole.

41.8 Layout

As Ada reads and writes the members of an object directly, the record of a class must have exactly the layout which the C++ compiler gives the class. The module works that layout out, and the wrapper file then holds a static assertion of the size of each class, and of the place of each of its public members, which fails when the wrapper file is compiled if the record does not match.

The checks are left out for a class whose layout cannot be worked out (the reason is given in a warning), and altogether where the wrapper file is compiled with SWIG_ADA_NO_LAYOUT_CHECKS defined.

A class which inherits a base class virtually (struct W : virtual V), and has no virtual function, is laid out as C++ lays it out: the record begins after the place of the pointer to the table through which C++ finds the virtual base, and has the virtual base last, once however many of its bases inherit it. For an object of the class itself, the component of the virtual base (the_W.V) is that base; a base class which has a virtual base is storage for its own part alone (W_storage), and is reached by as_W, as the place of its virtual base depends on the class which is derived from it. Ada cannot derive a type from such a class.

A class with virtual functions and a virtual base is a tagged type with no parent where it has no other base with virtual functions: its virtual base is last, and its primitives are its own virtual functions, one which overrides a function of the virtual base among them, as C++ lists them in its table. Where its virtual base has nothing but a pointer to a table (struct Named { virtual int name (); };), C++ shares that pointer, and the base is the parent of the type, as for single inheritance. C++ finds the virtual base through the table of the object, which an object that Ada declares has from C++; a type derived from the class in Ada would have a table which GNAT makes, in which C++ does not find it, so the spec says ahead of the type that none may be derived, and no director is made for it.

The usual reason for a record not to match is that the interface file does not show SWIG the whole class: a member is hidden by #ifndef SWIG, or a base class is never declared. An ignored member (%ignore) is not such a case, as its storage is still reserved.

41.9 Modules

A module which uses the types of another imports it with %import. Only the specifications of the importing module are written; those of the imported module come from its own run of SWIG, and are named in with clauses. A class of one module may be derived from a class of another, or have a member of one: the member variables of the imported class are read, so the record is laid out as C++ has the class, and that is checked when the wrapper is compiled. A function which overrides a virtual function of an imported class has the parameter and result types of that function, as it has within one module.

41.10 Warnings

The Ada module has four warnings, which name the file and the line of the declaration they are about, and may be turned off like any other (-w861, %warnfilter (SWIGWARN_ADA_NOT_BOUND) name;):

Number Name Meaning
861 SWIGWARN_ADA_NOT_BOUND A declaration is left out of the binding: a type is not known, a value cannot be stated in Ada, or an overload cannot be told apart.
862 SWIGWARN_ADA_LAYOUT A record may not have the layout of its class: a base class or a member could not be bound, or its size is not known.
863 SWIGWARN_ADA_VALUE A value could not be worked out, and another is used in its place (an enumeration value, the length of an array).
864 SWIGWARN_ADA_UNSUPPORTED A construct of C++ for which the module has no counterpart is bound only in part. It is no longer given: its uses, pointers to class members and virtual inheritance, are now bound.
